## 📌 Executive Summary

Every September at Lovely Professional University, student societies recruit in a high-energy frenzy. Within 3–4 weeks, **80–85% of recruits become "ghost members"** (muted WhatsApp groups, zero attendance). The entire organizational workload consolidates onto **2–4 burnt-out leads** who sacrifice their own CGPA, health, and exam preparation.

**ClubSync** is an empirical, human-centered onboarding protocol and interactive dashboard designed through the 5 stages of Design Thinking. Rather than creating another chat group, ClubSync transforms recruits into contributors within 72 hours through **calibrated commitments**, **45-minute micro-tasks**, **5-member peer pods with senior buddies**, and a stigma-free **"Exam Break" toggle**.

## 🧠 The 5 Design Thinking Stages (Full Documentation)

### Stage 1: Empathize (Weeks 3–5)
- **Field Evidence:** 6 qualitative, in-depth user interviews across technical, cultural, and literary societies with verbatim quotes.
- **AEIOU Framework Observations:** 2 structured campus field observations (Recruitment Corridor at Block 34 & General Body Meeting in Block 36 Auditorium).
- **Stakeholder Map:** Clear division of who suffers (leads & ghosts), who decides (leads & faculty), and who does the work (<8% of roster).
- **Empathy Maps:** Multi-quadrant synthesis (Says, Thinks, Does, Feels) for both President Aarav and Fresher Rohan.

### Stage 2: Define (Weeks 5–6)
- **User Personas:** Grounded archetypes for *Aarav Sharma* (Burnt-out President, CGPA dropped 8.6 -> 7.4) and *Rohan Verma* (Disillusioned Fresher).
- **As-Is Journey Map:** Detailed touchpoint mapping highlighting the drop-off cliff at Week 2–3.
- **POV Formulation:** 
  > *Overworked club leads need a structured, low-risk way to delegate concrete micro-tasks to new recruits with verifiable milestones, because vague broadcast requests cause failure and force leads back into solo burnout.*
- **Core HMW Question:**
  > *How might we equip club leads to assign actionable, 45-minute starter tasks to every new recruit within 48 hours of joining so that passive sign-ups immediately convert into active contributors?*

### Stage 3: Ideate (Weeks 6–7)
- **31 Divergent Concepts** generated across Brainstorming, SCAMPER, Crazy 8s, and Analogous Open-Source frameworks.
- **Weighted Screening Matrix:** Evaluated against Desirability (35%), Feasibility (35%), and Sustainability (30%).
- **Selected Solution:** *ClubSync Protocol* (Score: 4.78/5.00), outscoring AI bots and punitive rating systems.

### Stage 4: Prototype (Weeks 9–10)
- **Evolutionary Prototypes:** From paper wireframes to a responsive HTML5/CSS3/JavaScript web application.
- **Key Modules:** 1-page compact onboarding form, SMART task cards, 5-member pod structure, and lead health dashboard.

### Stage 5: Test & Iterate (Weeks 11–12)
- **Usability Testing:** Evaluated with 7 campus participants (5 recruits, 2 leads) following a strict neutral, silent observation protocol.
- **Prioritized Usability Fixes:**
  - *High Severity:* Eliminated 4K image bloat to ensure instant loading on campus Wi-Fi.
  - *High Severity:* Added explicit psychological safety banners to overcome fresher draft evaluation anxiety.
  - *Medium Severity:* Replaced confusing corporate term "Sabbatical" with student-friendly "Take an Exam Break".

## 🎤 Viva Defense & Explanation Guide (for Faculty Evaluation)

When explaining this project to the faculty evaluator, use this structured 2-minute elevator narrative:

1. **The Core Realization (Why technology wasn't the first answer):**
   > *"Faculty often expect an app for everything. But our field research with 6 club presidents and ghost members revealed that ghosting is not an app problem—it is an **onboarding and psychological safety breakdown in the first 72 hours**. Freshers felt intimidated and invisible; leads were terrified of bad event outcomes so they hoarded tasks."*

2. **The Key Pivot:**
   > *"We initially planned to build a public club review portal ('Yelp for clubs'). But user interviews killed that assumption: members told us the recruitment pitch wasn't the issue; the lack of a clear, low-stakes starter task after joining was. We pivoted our entire design to the **ClubSync Onboarding Protocol**."*

3. **Demonstrating Empirical Impact:**
   > *"In our usability trials, 4 out of 5 recruits completed their starter task within 72 hours (compared to the historical 20% baseline), and club leads cut their pod diagnosis time from 2 hours to 22 seconds using the color-coded health dashboard."*

## 🛠️ Full-Stack System Architecture & Local Setup

ClubSync operates as an end-to-end full-stack web application with dual-mode deployment:
1. **Full-Stack Mode (Local / Production Server):** Powered by an asynchronous Node.js microservice (`server/server.js`) with an atomic JSON database (`server/data.json`) exposing a fully-fledged REST API.
2. **Decoupled Client Mode (GitHub Pages):** Functions seamlessly on static CDN hosts with automated fallback state management, allowing evaluators to interact with the full user journey without setting up an external backend.

### REST API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/api/stats` | Real-time executive metrics (Total recruits, active sprints, exam pauses, at-risk pods, activation %) |
| `GET` | `/api/pods` | Functional pods with member rosters, task completion rates, and blocker alerts |
| `POST` | `/api/enroll` | Recruits register skills & weekly hours; auto-assigned to balanced 5-member pod + mentor + 45-min starter task |
| `POST` | `/api/tasks/:id/submit` | Verifies micro-task submissions and updates pod health status in real time |
| `PATCH` | `/api/members/:id/toggle-pause` | 1-Click dignified Exam Break toggle (silences sprint alerts without roster removal) |

### 🚀 Running the Full-Stack Server Locally

```bash
# Clone the repository
git clone https://github.com/rajoob-Ai/Ghost-Members-and-Burnout-Leads.git
cd Ghost-Members-and-Burnout-Leads

# Start the full-stack server (Zero npm dependencies required!)
npm start
# or: node server/server.js

# Open in browser:
# Web App: http://localhost:3000
# REST API Stats: http://localhost:3000/api/stats
# REST API Pods: http://localhost:3000/api/pods
```

## 🛠️ Tech Stack & Architecture

- **Backend:** Node.js (v18+) REST API HTTP microservice (`server/server.js`), Atomic JSON Data Store (`server/data.json`)
- **Frontend:** Vanilla HTML5, CSS3 (Modern Flexbox/Grid), JavaScript (ES6+) asynchronous client (`public/js/api.js`)
- **Design System:** Plus Jakarta Sans & JetBrains Mono typography, responsive mobile-first architecture
- **Zero Third-Party Dependencies:** Ultra-lightweight payload (<150KB) designed specifically to run reliably in low-connectivity campus corridors and basement labs.
- **Deployment:** GitHub Pages (Automated Continuous Deployment) & Local Node.js runtime
